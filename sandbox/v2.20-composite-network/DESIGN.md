# NEXUS V2.14 情景市值设计规范

V2.14 冻结 V2.13，将公司经营桥接结果转成实际股权价值金额。原引擎字段只作为收入、利润率、倍数和 FCF 的情景输入，不再形成独立“价值压力”输出。

## 市值重估契约

1. 当前市值、市场倍数和财务底座都必须记录币种、日期、来源状态与审核状态。
2. 基准股权价值使用当前市值校准，避免缺少完整预测期时伪造独立目标价。
3. 冲击只通过 EBITDA / 净利润、倍数和 FCF / 净债务桥接进入股权价值。
4. 公司排名按 `valueChangePct` 排序，同时显示 `valueChangeAmount`；不同币种金额不得直接比较。
5. 经营变化、倍数变化和 FCF / 净债务三项金额必须严格回加到总市值变化。
6. 页面、公司节点、财务抽屉、A/B 对照和导出读取同一估值引擎，不能保留第二套分数排名。

## 状态契约

当前输出为 `CANDIDATE_VALUATION`。市场数据来自第三方数据提供商或结构化搜索结果，未通过 T1/T2 原文定位门禁，继续保持 `NEEDS_HUMAN_REVIEW / formal_ready=false / NOT_IDENTIFIED / ABSTAIN`。这些状态限制证据与因果主张，不阻止页面展示明确标注的候选计算结果。

## 版本组件

- `market-valuation-data.js`：冻结 15 家公司的行情、市场倍数、财务日期和来源状态。
- `market-valuation-engine.js`：执行 AI EV/EBITDA 与煤钢 P/E 重估。
- `v214-market-value-ui.js`：统一覆盖排名、五项估值账、财务桥接、瀑布与 A/B 对照。
- `run-manifest.js`：记录领域包、市场数据版本、估值引擎版本和审核状态。

## NEXUS V2.13 公司估值设计规范

V2.13 冻结 V2.12，在现有领域引擎与页面之间新增严格估值契约。产业引擎继续输出经营变化和价值压力归因分数；估值契约单独读取市场事实、财务底座和方法参数，计算股权价值金额。两者不得互相代替。

## 两层价值语义

1. `company.valuation`：历史字段名，V2.13 展示层统一解释为 `attributionScore`，单位是模型归因分数。
2. `companyValuationResults`：严格估值输出，单位是对应币种的十亿；只有输入完整且通过数值门禁时才产生金额和百分比。
3. 归因分数可以解释政策、需求、供给、利润率、CapEx 与倍数如何形成压力，但不能直接乘以当前市值。
4. 公司节点颜色与相对排序仍可使用归因分数，必须同时显示“非公司估值”边界。

## 估值输入契约

所有方法都要求当前股价、稀释后股数、市值日期、现金、有息债务和非经营性资产。

- `EV_EBITDA` 额外要求基准 EBITDA 与经审核的 EV/EBITDA 倍数。
- `DCF` 额外要求逐年 FCF、WACC 与终值增长率。
- `MARKET_FACT / REPORTED_ACTUAL / CALIBRATED_PARAMETER` 才能进入计算。
- `DATABASE_CANDIDATE / NEEDS_HUMAN_REVIEW / DATA_MISSING` 均阻断结果。
- 不用零值填补缺失债券、债务、现金、非经营性资产或预测期数据。

## 输出契约

每家公司输出：

```text
currentMarketCap
baselineEquityValue
scenarioEquityValue
valueChangeAmount
valueChangePct
marketUpsidePct
attributionScore
missingInputs / invalidInputs
method / currency / scale / dataCutoff
```

`DATA_MISSING` 时前六个字段必须为 `null`。数值齐全但 WACC 不高于终值增长率、倍数非正、股价非正或股权价值非正时返回 `ABSTAIN`。

## 数据与时间门禁

煤钢候选财务字段来自只读 PostgreSQL 三张合并报表，使用 `statement_type='408001000'`，且 `actual_ann_dt/ann_dt` 与 `opdate` 均不晚于 2026-05-08。每个候选值保留报告期、可见日期和 `opdate`。当前缺少市场行情与股数表，因此不计算当前市值或股价空间。

## NEXUS V2.12 多领域设计规范

V2.12 冻结 V2.11，新增领域路由层。六列只复用结构角色和交互框架，不复用具体行业节点。选择领域后，页面在启动共享模块前一次性加载该领域的数据、语义、模型配置、计算引擎、领域契约、公司适配器、图包和数据库快照。

## 领域隔离契约

1. `domain=ai-infrastructure` 与 `domain=coal-steel` 使用互斥资源清单，不在同一页面运行时混装两个 `SANDBOX_DATA`。
2. 切换领域必须整页重载，防止旧节点、旧引擎、旧证据注册表和旧公司状态残留。
3. 六个固定结构角色是宏观、需求、路线、约束、价值池和公司；每个领域自行提供标题、节点、边、情景词典与公司依赖。只有定义、单位和时间口径一致的通用变量（当前仅 `rates`）允许显式复用 ID。
4. 公司切换只在当前领域包内重新编译依赖图；未登记公司返回 `ABSTAIN`，不得从其他领域寻找近似节点。
5. 情景保存键、导出文件和运行清单必须包含 `domainId`；相同输入、相同领域包和相同参数版本产生确定性图哈希。
6. 煤钢数据库值只标记为 `DATABASE_CANDIDATE / CALCULATED_LINEAGE_CANDIDATE`，缺少原文定位和快照哈希时继续 `NEEDS_HUMAN_REVIEW`。
7. 两个领域的正式状态固定为 `formal_ready=false / NOT_IDENTIFIED / ABSTAIN`，直到各自完成证据、校准与历史回放门禁。

## NEXUS V2.11 公司经营与估值口径对齐

V2.11 冻结 V2.10，并修正公司层的展示口径。产业网络在进入公司之前表达宏观、需求、路线、供给余量和价值池传播；公司节点则切换到同一财务引擎产生的收入模型变化和估值贡献，避免把需求下降释放的闲置产能直接解释为公司利好。

## 公司节点口径

- 主值：`company.revenue`，显示为“收入模型变化”。
- 次值：`company.valuation`，显示为“估值贡献”，与公司排名一致。
- 公司节点边框：按估值贡献方向着色。
- 进入公司的连线：按收入模型方向着色；边级原始贡献仍保留在追溯面板，并标为产业暴露输入。
- 供给余量正值只表示瓶颈缓解或闲置余量增加，不自动证明收入、利润或估值改善。
- 所有公司数值仍是 `MODEL_PROTOTYPE_ONLY`，不得解释为披露预测或事实因果影响。

## V2.10 设计规范

V2.10 以冻结的 V2.9 为父版本，保留六列产业网络和公司解析图，在公司点击路径中增加财务传导检查器。该检查器是展示适配层，只读取当前引擎结果，不复制公司计算数据，也不改变传播或估值公式。

## 公司财务传导契约

1. 点击网络公司节点、公司排名、情景对比公司行或公司选择器后，直接打开所选公司的财务传导。
2. 固定显示营业收入、营业利润影响代理、自由现金流与估值贡献四步；每步必须提供公式、分类、谱系 ID、解释和失效条件。
3. 桌面使用右侧抽屉，窄屏使用底部抽屉；关闭后恢复触发控件焦点。
4. 回放阶段 6 打开财务桥接，阶段 7 定位估值贡献；动画不参与计算。
5. `DATA_MISSING` 时精确百分比只能称为演示性模型变化，不能称作披露预测、目标价、预期回报或事实因果影响。
6. 只有 T1/T2 可支持来源事实；当前门禁固定为 `EXPOSURE_ONLY / NEEDS_HUMAN_REVIEW / formal_ready=false / NOT_IDENTIFIED / ABSTAIN`。

V2.9 增加“领域包 + 公司依赖 + 解析图”编译阶段。六列仅作为结构角色复用，具体节点由领域包提供；公司切换时重新计算必要上游闭包，允许某家公司在不适用的层内没有节点。

## 解析图契约

- 领域包必须声明固定六类结构角色、节点、边、情景字典和公司清单。
- 公司配置必须声明公司节点、必要产业输出、业务分部、模型族和证据状态。
- 编译器输出节点、边、活动情景路径、逐层数量、缺失依赖、输出等级和确定性图哈希。
- 未登记公司或缺失依赖返回 `ABSTAIN`，不得用相似公司的节点替代。
- 当前 AI 包仍通过过渡适配器读取旧数据；下一领域包必须直接提供自身节点与边。

V2.8 保留 V2.7 的传播播放与 V2.6 的量纲门禁，增加数据库覆盖审计。数据库连接仅允许读事务；数据库不覆盖目标公司时，公司输出必须降级，不能用其他市场的同号证券替代。

## 数据库时间门禁

- 以 `COALESCE(NULLIF(actual_ann_dt,''), ann_dt)` 判断公开可见日期。
- 优先使用 `statement_type='408001000'`。
- `opdate` 不得晚于数据截止时间，并用于同一证券、报告期和公告日期内的版本排序。
- 缺失值不补零；没有当时可见版本时返回 `DATA_MISSING`。
- 当前三表仅覆盖 A 股，首期五家海外公司均不得输出 L2/L3 财务结论。

V2.6 保留 V2.5 的“全景探索 + 主路径复算 + 契约层”作为父版本，新增量纲一致性门禁。直接输入、模型传播、供给余量、产业价值池、经营暴露和估值贡献必须分别标识。真实披露资料尚未完成逐条定位，因此本版本仍是候选研究原型。

## 契约优先层

- 节点必须登记指标名称、指标类型、单位、币种、基准值、会计期间、数据截止时间、来源分类和可编辑状态。
- 证据必须登记证据 ID、文件、发布主体、发布日期、原文摘录、稳定定位、原始链接、支持节点和审核状态。
- 缺少原文、定位、发布日期或快照哈希时，状态保持 `NEEDS_HUMAN_REVIEW`；不以综合分数掩盖缺口。
- 每次运行必须记录领域包版本、公司模型版本、数据截止时间、证据版本、参数版本、运行时间和情景输入。

## 领域包与公司适配器

AI 基础设施包登记固定六层、情景词典、五类模型族和证据策略。公司适配器根据事前暴露推荐影响因素和输出等级；未登记公司返回 `ABSTAIN`，不自动生成结论。

V2.4 从 V2.2 的可检查研究实验台继续升级为“全景探索 + 主路径复算”的金融世界沙盘。它仍然是情景模拟，不是事实因果识别或目标价系统。

## V2.4 交互闭环

1. 在世界网络中选择公司或节点；
2. 切换“可复算”页签，查看该公司从冲击到估值的主路径；
3. 点击任一步骤，查看输入、公式、参数区间、时间权重、证据分类和失效条件；
4. 对可编辑节点拖动冲击滑块，结果回到同一套 V2.2 引擎重新计算；
5. 使用研究视角和证据筛选，区分全景、主路径、事实入口与模型假设。

全景视图负责定位关系，逐步账本负责解释关系；两者不产生第二套手工计算。

## 三个核心视图

1. 世界网络：观察冲击在宏观、需求、技术、供给、产业链与公司之间传播。
2. 公司模型：沿产业暴露、收入、利润率、资本开支、FCF、估值倍数解释公司结果。
3. 情景实验室：比较 A/B 情景、3/12/36 个月阶段，以及低/基准/高参数区间。

## 研究契约

- SOURCE_FACT 仅允许 T1/T2 原始材料支持。
- 公开披露只确认业务暴露，不直接支持传播弹性与估值幅度。
- 弹性、时滞、财务敏感度和估值参数属于 MODEL_ASSUMPTION。
- 所有输出为 SCENARIO_RESULT，因果状态固定为 NOT_IDENTIFIED，结论为 ABSTAIN。
- 证据缺少原文摘录或页级定位时显示 NEEDS_HUMAN_REVIEW。

## 时间语义

- 3M 即时阶段：订单、价格、政策与瓶颈利用率首先变化。
- 12M 经营阶段：收入、利润率、资本开支和营运资本开始体现。
- 36M 结构阶段：扩产、技术替代、份额与估值中枢发生变化。

低、基准、高不是概率置信区间，而是传播参数敏感性区间。

## V2.1 可见性修订

财务桥接不再只存在于公司模型页。世界网络主视图必须始终显示所选公司的产业暴露、收入、利润率、CapEx、FCF 和估值，并提供公司实时排名。快捷情景、传播动画、关键路径和冲击强度编辑属于核心工作流，不得因研究视图拆分而隐藏。

## V2.2 研究模型修订

### 边级动态传播

每条传播边独立记录低/基准/高弹性、有效延迟、爬坡期、持续期、衰减期、可逆性、置信度、证据类别、证据 ID 和失效条件。3M / 12M / 36M 结果由边级时间响应计算，不再采用全局图层缩放。

### 公司专属模型

- NVIDIA / AMD：出货量 × ASP × 系统附加率；
- SK hynix / Micron：Bit 出货 × 价格 × HBM 组合 − 扩产；
- TSMC：先进晶圆 + 先进封装 − 折旧与 CapEx；
- Arista / Vertiv / Eaton / Broadcom：订单、积压转化和交付能力；
- Microsoft：云使用量与 AI 变现 − CapEx − 新增折旧。

公司模型仍为 `MODEL_ASSUMPTION`，不冒充公开披露公式或目标价模型。

### 对照、版本与审计

A/B 估值差必须可回加为政策、需求、供给、利润率、CapEx 和倍数六项。用户编辑参数后保留字段级变更记录，并可保存、载入或导出情景。导出不得改变 `NEEDS_HUMAN_REVIEW`、`formal_ready=false` 或 `NOT_IDENTIFIED / ABSTAIN`。

### 六层横向坐标

世界网络的宏观/政策环境、需求驱动、技术路线竞争、供给约束/产能瓶颈、产业链环节与节点、公司六个标题必须与节点使用同一组横向中心和列边界。缩放只改变纵向展开与节点密度，不压缩横向产业层；窄屏保留最小逻辑宽度并横向滚动。
