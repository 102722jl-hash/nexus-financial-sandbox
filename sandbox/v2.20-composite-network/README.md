# NEXUS V2.20 复合网络编译工作台

V2.20.0 以 `V2.19.13-frozen` 为冻结父版本，在原有自动画像、候选传播和动态网络上增加行业无关的复合编译层。每次导入分别输出 `DATA_READY / GRAPH_READY / SCENARIO_READY`，并检查字段覆盖、节点分类、断链、循环、公式、单位和可调节点到结果节点的可达路径。

## 新采集器统一格式

所有新行业采集器统一输出 `nexus-crawler-batch-1.0.0` JSON 批次，固定包含 `network / batch / sources / documents / evidence / layers / entities / metric_definitions / observations / formulas / relations`。网页总标题读取 `network_name`，节点分类读取指标的 `default_layer_code`，节点与关系由稳定 ID 编译，不再按行业写死前端逻辑。

入库前执行：

```powershell
python validate_crawler_payload.py v220_crawler_payload.example.json
```

完整说明见 `V2.20-CRAWLER-DATA-CONTRACT.md`；机器 Schema、完整示例和 PostgreSQL 参考表结构分别见 `v220_crawler_payload.schema.json`、`v220_crawler_payload.example.json`、`v220_reference_schema_postgresql.sql`。

通过校验后可以确定性编译网络：

```powershell
python compile_crawler_network.py <批次文件>
```

需要写入 PostgreSQL 时使用 `crawler_postgres_ingest.py`。该入口采用稳定主键和增量 `ON CONFLICT` 写入，不执行 `TRUNCATE`，同一批次重复执行不会重复生成节点、关系或指标值。

新能源汽车采集器已经接入这一出口。每日任务完成原有质量门禁后，会生成标准批次并更新 V2.20 的浏览器网络文件；质量门禁失败时只保留批次，不发布新网络。

# NEXUS V2.17 冻结基线

V2.17 以 V2.16 为冻结父版本，增加本地连接器、只读 PostgreSQL/MySQL 元数据画像、人工确认字段映射和确定性情景 API。浏览器只访问本机 `127.0.0.1:4178`，不会直接连接用户数据库或 AI 服务；V2.16 及更早目录均保持不变。

## V2.17 连接器

- 数据库连接：PostgreSQL、MySQL；文件画像：CSV、Excel、JSON、SQLite。
- 数据库会话强制只读事务，只执行固定的 `information_schema` 元数据查询，不接受浏览器提交的任意 SQL。
- 密码仅用于当前请求，或通过本机环境变量 `credentialRef` 引用；不写入磁盘、日志、任务哈希、LocalStorage 或 API 响应。
- AI 仅生成字段映射、候选关系和结果解释；所有候选均带 `confidence / reason / evidence`，必须人工确认。
- 情景数值由确定性引擎计算，AI 不能修改数值、权限、关系或证据状态。

## V2.16 新增

- 确定性领域解析器：基于文件名、字段、公司和证券代码对 AI 基础设施、焦煤—钢铁和新能源汽车候选领域评分。
- 导入意图区分：补充快照、替换完整快照或建立新领域候选。
- 网络差异预览：显示新增、移除、更新、共享、不可用节点和行业外字段。
- 公司门禁：已登记公司匹配现有适配器；未知公司只能进入 `EXPOSURE_ONLY / COMPANY_ADAPTER_REQUIRED`。
- 双重人工确认：指标映射和网络差异都确认后才能构建候选包。
- 候选包激活：同领域以候选快照标记已映射节点；跨领域重载完整领域资源，不混用旧行业节点。
- 未实现领域隔离：新能源汽车可以形成候选包，但保持 `CREATE_DOMAIN_CANDIDATE / ABSTAIN`，不能进入估值。
- 时间门禁：CSV、Excel、JSON 和 SQLite 中可识别的日期晚于数据截止时间时进入 `QUARANTINED_AFTER_CUTOFF`。
- 标准包增加 `data_snapshot.json`、`company_adapters.json`、`network_diff.json` 和 `activation.json`。

# NEXUS V2.14 情景市值重估

V2.14 以 V2.13 为冻结父版本，按用户要求删除“价值压力”产品概念，把产业冲击和公司经营结果直接接入市场校准估值模型。公司排名现在依据冲击后股权价值相对基准价值的变化比例，并同时显示本币市值变化金额。

## V2.14 输出

- 当前市值：行情数据提供商候选市值，带报价或检索日期。
- 基准情景股权价值：市场校准至当前市值。
- 冲击后股权价值：经营变化、估值倍数和 FCF / 净债务进入公司估值公式后的结果。
- 情景价值变化：冲击后股权价值减基准股权价值，显示本币金额与比例。
- 相对当前市值空间：冲击后股权价值除以当前市值减一。
- 公司排名：按情景价值变化比例从高到低排序，避免不同币种金额直接混排。

## 估值方法

AI 十家公司使用市场校准 `EV/EBITDA`：

```text
基准 EBITDA = 当前市值 / (EV/EBITDA − 净债务/EBITDA)
情景 EBITDA = 基准 EBITDA × (1 + 收入变化 + 利润率影响)
情景倍数 = 基准 EV/EBITDA × (1 + 倍数变化)
情景净债务 = 基准净债务 − 增量 FCF
情景股权价值 = 情景 EBITDA × 情景倍数 − 情景净债务
```

煤钢五家公司使用市场校准 `P/E`：

```text
基准 P/E = 当前市值 / 2025 年净利润
情景净利润 = 基准净利润 × (1 + 收入变化 + 利润率影响)
情景 P/E = 基准 P/E × (1 + 倍数变化)
情景股权价值 = 情景净利润 × 情景 P/E
```

## 数据现状

只读 PostgreSQL 查询已验证 `transaction_read_only=on`。煤钢五家公司截至 2026-05-08 可获得 2025 年报口径的 EBITDA、FCF、货币资金及主要债务组件，查询按 `statement_type='408001000'`、公告日期和 `opdate` 选择当时可见版本。这些值仍是 `DATABASE_CANDIDATE`，没有原文定位与快照哈希，不能进入正式估值。

现有三张表缺少当前股价、市值和稀释后股数；债务组件尚未完成口径审核，估值倍数、非经营性资产及 DCF 预测参数也未闭环。因此 AI 与煤钢公司当前均显示 `DATA_MISSING`，不生成虚假的价值变化金额或股价空间。

## 估值公式

```text
EV / EBITDA：
企业价值 = 情景 EBITDA × 估值倍数
股权价值 = 企业价值 − 有息债务 + 现金 + 非经营性资产

DCF：
股权价值 = 预测期 FCF 现值 + 终值现值 − 有息债务 + 现金 + 非经营性资产

情景价值变化 = 冲击后股权价值 − 基准情景股权价值
相对当前市值空间 = 冲击后股权价值 / 当前市值 − 1
```
