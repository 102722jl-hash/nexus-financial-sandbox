# 多行业金融世界沙盒设计方案 V1.0

> 文档状态：设计基线
>
> 适用范围：静态金融沙盒、本地数据连接器、AI 辅助数据映射、多行业领域包、公司适配器和可审计任务调度。
>
> 当前示范领域：焦煤—钢铁。后续验证领域：AI 基础设施、新能源汽车、银行、医药。

## 1. 目标

建设一套“通用引擎 + 行业领域包 + 公司适配器 + 可选 AI 接入层”的金融研究沙盒。

用户改变一个现实变量后，系统展示：

```text
现实变量
  → 行业机制
  → 产业链节点
  → 公司经营指标
  → 收入 / 利润 / FCF
  → 估值贡献
```

系统必须满足：

- 支持多个行业，不因行业节点不同而产生错误匹配；
- 同一行业中允许不同公司的业务暴露和模型不同；
- 用户可以上传文件、连接只读数据库或加载预制数据包；
- AI 可以辅助识别字段和推荐模型，但不能直接替代规则、证据门禁或金融计算；
- 已确认的映射、参数和数据包可以脱离 AI 离线复现；
- 所有结果可以追溯到输入、公式、参数、时间和证据；
- 数据不足时降级或拒绝输出，不补零、不伪造精确估值。

## 2. 非目标

本系统不是：

- 自动识别一切数据并保证正确的黑盒 AI；
- 自动做现实因果识别的工具；
- 自动生成投资建议或目标价的系统；
- 把所有公司套用同一条“输入变化 × 弹性”公式的 Dashboard；
- 强制所有行业都具备完整六层节点的固定模板。

产品输出是条件情景推演。没有严格因果识别时，因果状态必须为 `NOT_IDENTIFIED`，结论必须为 `ABSTAIN`。

## 4. 四个核心层次

### 4.1 通用沙盒引擎

所有行业共用，不包含具体行业事实：

- 情景解析；
- 六层网络布局和缩放；
- 节点、边、时间延迟和反馈回路；
- 低 / 基准 / 高情景计算；
- 财务桥接和估值贡献；
- 关键路径、二阶影响和反直觉结果；
- 公司排名和敏感性分析；
- 证据、参数和运行清单追溯；
- 历史回放和离线复现。

计算引擎必须是确定性的：相同领域包、数据快照、参数、输入和版本，产生完全一致的结果。

### 4.2 行业领域包

领域包是可版本化的行业知识，不是长提示词。每个领域包定义：

- 六层语义；
- 必选节点和可选节点；
- 节点指标类型、单位、币种和基准；
- 产业链边及其经济含义；
- 情景词典；
- 模型家族；
- 估值方法；
- 行业证据要求；
- 缺失数据和降级规则。

示例目录：

```text
domains/
├── coal-steel/v1.0.0/
├── ai-infrastructure/v1.0.0/
├── new-energy-vehicle/v1.0.0/
├── banking/v1.0.0/
└── pharma/v1.0.0/
```

六层标题保持稳定，但节点可以因领域而变化：

```text
煤炭—钢铁：焦煤价格 / 高炉 / 港口库存 / 特钢
银行：利率 / 贷款需求 / 净息差 / 不良率 / 拨备
医药：医保政策 / 处方量 / 临床进度 / 研发费用 / 产品组合
```

### 4.3 公司适配器

公司适配器负责处理同一行业内的差异：

```text
公司实体
  → 业务分部
  → 产业节点暴露
  → 暴露权重
  → 模型家族
  → 财务字段
  → 输出等级
```

公司适配器至少包含：

- 证券代码、公司名称和行业；
- 业务分部及收入 / 利润 / 资产 / 订单暴露；
- 核心经营指标；
- 经营指标到财务报表的公式；
- 财务指标到估值贡献的公式；
- 时间延迟、反证和失效条件；
- 证据状态和数据覆盖状态。

### 4.4 AI 辅助接入层

AI 只负责不确定的语义任务：

- 字段语义识别；
- 行业和公司候选匹配；
- 指标类型判断；
- 合并报表 / 母公司口径候选判断；
- 公司模型家族推荐；
- 文档中的指标候选提取。

AI 输出必须是 `PENDING_REVIEW` 候选。人工确认后才可以写入冻结映射，确定性引擎不得直接读取未审核的 AI 输出。

## 5. 数据接入方式

### 5.1 标准数据包

适用于不需要 AI 的静态演示和离线复现。用户加载已经确认的数据包：

```text
industry-package/
├── manifest.json
├── domain.json
├── data-snapshot.json
├── metric-mapping.json
├── company-adapters.json
├── model-parameters.json
├── evidence-index.json
├── quality-report.json
└── quarantine.json
```

### 5.2 文件上传

支持：

- CSV；
- Excel；
- JSON；
- SQLite；
- 年报、半年报、季报和公告 PDF。

文件先进入暂存区，不得直接进入计算引擎：

```text
staging/
├── uploaded_files/
├── extracted_tables/
├── document_candidates/
├── schema_profile.json
└── import_manifest.json
```

### 5.3 数据库连接

支持 MySQL 和 PostgreSQL 的只读连接。连接配置：

```text
数据库类型
主机与端口
数据库名称
只读用户名
凭据引用
数据截止时间
允许访问的表或 schema
```

安全要求：

- 必须使用只读账号；
- 每个会话执行 `SET SESSION TRANSACTION READ ONLY` 或等价配置；
- 密码不进入前端构建包、领域包、运行清单或日志；
- 默认只读取表结构、字段统计和有限样例；
- 不允许把任意数据库密码发送给 AI；
- 后端和本地连接器都应设置查询超时、行数上限和表白名单。

### 5.4 文档接入

文档提取结果必须保留：

- 文件名；
- 发布主体；
- 发布日期；
- 页码、表格或段落定位；
- 原文摘录；
- 原始链接；
- 快照路径和 SHA256；
- 支持的节点 ID；
- 审核状态。

搜索摘要、AI 摘要和媒体转述不能直接升级为 `SOURCE_FACT`。

## 6. 数据识别与分类流程

```text
1. 创建接入任务
2. 保存数据来源和截止时间
3. 扫描表、字段、类型、行数和样例
4. 规则完成确定性识别
5. AI 对不确定项生成候选映射
6. 执行单位、币种、期间和口径检查
7. 用户审核映射
8. 生成标准数据快照
9. 匹配领域包和公司适配器
10. 生成缺失 / 冲突 / 隔离报告
11. 构建可加载数据包
12. 在沙盒中运行和回放
```

### 6.1 规则优先

不需要 AI 的内容由规则完成：

- 股票代码和公司名称字典；
- 日期和会计期间；
- 币种和单位；
- 行业代码；
- 常见会计科目；
- 报表类型；
- 重复记录和空值比例；
- 数据截止时间；
- 表结构和字段类型。

### 6.2 AI 候选映射

AI 返回结构化 JSON，不允许返回不可解析的自由文本作为映射结果：

```json
{
  "source_column": "TOT_OPER_REV",
  "candidate_metric": "revenue",
  "metric_type": "financial_flow",
  "confidence": 0.98,
  "reason": "字段名称与合并利润表营业总收入一致",
  "status": "PENDING_REVIEW"
}
```

### 6.3 人工确认和冻结

确认后生成版本化映射：

```json
{
  "mapping_version": "coal-db-map-1.0.0",
  "source": "workspace.financial_statements",
  "columns": {
    "S_INFO_WINDCODE": "company_code",
    "REPORT_PERIOD": "accounting_period",
    "TOT_OPER_REV": "revenue",
    "NET_PROFIT": "net_profit",
    "NET_CASH_FLOWS_OPER_ACT": "cfo"
  },
  "review_status": "HUMAN_CONFIRMED"
}
```

未确认的映射只能用于预览，不能用于正式候选包。

## 7. 节点匹配机制

节点不是简单的“存在 / 不存在”，而是有匹配状态：

| 状态 | 含义 | 允许输出 |
|---|---|---|
| `MATCHED` | 数据和业务含义均能对应 | 正常进入模型 |
| `PARTIAL` | 只能确认部分业务暴露 | 区间或方向判断 |
| `UNAVAILABLE` | 没有数据或无法确认含义 | 不进入对应公式 |
| `CONFLICTED` | 多个来源、单位或期间冲突 | 进入隔离区 |
| `OUT_OF_SCOPE` | 当前领域包不支持 | 不参与当前运行 |

公司输出等级：

```text
L3             收入、利润、FCF 和估值贡献完整计算
L2             低 / 基准 / 高区间
L1             正面、负面或不确定方向
EXPOSURE_ONLY  仅展示潜在关联路径
ABSTAIN        证据不足，拒绝输出结论
```

节点缺失时的处理：

- 不用零值填补；
- 不把相邻节点强行当作替代变量；
- 删除受影响的传播边；
- 在 UI 显示缺失原因；
- 自动降低公司输出等级；
- 保留 `quality-report.json` 和 `quarantine.json`。

## 8. 模型设计

### 8.1 模型类型

所有指标必须声明类型，不能只保存一个无单位的百分比：

```text
价格、数量、金额、存量、流量、利用率、利润率、库存、估值贡献
```

### 8.2 公司模型家族示例

煤炭—钢铁领域：

```text
DIVERSIFIED_MINER
煤炭售价 × 销量 + 电力与运输缓冲

PURE_MINER
煤炭售价 × 销量 − 单位成本

MIXED_MINER
煤炭量价 + 煤化工组合 − 扩产投入

INTEGRATED_STEEL
钢材订单 − 焦煤成本 + 高炉利用率

SPECIAL_STEEL
特钢订单 + 产品组合 − 原料成本
```

银行领域可使用：

```text
NET_INTEREST_MARGIN
生息资产 × 净息差 − 信用成本

RETAIL_BANK
零售贷款 × 净息差 + 财富管理收入 − 拨备
```

### 8.3 传播边

每条边必须包含：

```text
edge_id
from / to
经济含义
低 / 基准 / 高参数
时间延迟、爬坡、持续和衰减
是否可逆
证据类别
失效条件
```

没有校准依据的参数必须标记为 `ANALYST_ASSUMPTION`。反馈回路必须说明经济含义、时间范围、收敛条件和上限。

## 9. AI 服务抽象

AI 不写死在行业引擎中，通过统一接口接入：

```javascript
class AIProvider {
  testConnection() {}
  profileColumns() {}
  suggestFieldMappings() {}
  classifyDomain() {}
  recommendCompanyModel() {}
  extractDocumentMetrics() {}
}
```

支持：

- OpenAI-compatible 云服务；
- 企业内部模型网关；
- Ollama 等本地模型；
- 完全关闭 AI，使用手工映射。

API 配置不属于领域包。领域包只记录模型接口能力和提示模板版本，不记录密钥。

建议 API：

```text
GET  /health
POST /ai/test
POST /sources/profile
POST /mappings/suggest
POST /mappings/validate
POST /packages/build
GET  /packages/{package_id}
```

AI 发送数据分级：

| 级别 | 内容 |
|---|---|
| 最小 | 表名、字段名、字段类型 |
| 推荐 | 字段画像、空值率、少量脱敏样例 |
| 文档 | 用户明确选择的文档片段 |
| 禁止 | 密码、完整连接串、无关客户数据 |

## 10. 任务调度设计

### 10.1 任务类型

```text
IMPORT_SOURCE       导入文件或连接数据库
PROFILE_SOURCE      扫描表结构和字段画像
AI_MAPPING          生成候选字段映射
ENTITY_RESOLUTION   公司、行业和证券代码对齐
EVIDENCE_EXTRACT    提取文档证据
VALIDATE_DATA       数据、单位、期间和证据门禁
BUILD_PACKAGE       构建标准领域数据包
RUN_SCENARIO        运行情景模型
SENSITIVITY         执行敏感性分析
REPLAY_RUN          历史回放或离线复现
EXPORT_RESULT       导出输入、结果和审计清单
```

### 10.2 状态机

```text
CREATED
  → QUEUED
  → RUNNING
  → WAITING_REVIEW
  → SUCCEEDED

RUNNING → RETRY_WAIT → RUNNING
RUNNING → FAILED
任何阶段 → QUARANTINED
```

状态含义：

- `WAITING_REVIEW`：需要人工确认映射或证据；
- `RETRY_WAIT`：可重试的临时错误；
- `FAILED`：任务技术失败，但不代表数据可以使用；
- `QUARANTINED`：数据、证据或映射不满足门禁；
- `SUCCEEDED`：仅代表该任务完成，不代表正式研究可用。

### 10.3 调度优先级

```text
P0  用户当前页面的预览运行
P1  字段画像和映射建议
P2  证据提取和批量构建
P3  历史回放、敏感性分析和定时校准
```

同一 `run_id + input_hash + config_hash` 的任务必须幂等。重复提交时返回已有任务，不重复调用 AI 或写入新结果。

### 10.4 资源和并发

- 每个用户限制并发导入任务数量；
- 数据库扫描设置连接、查询、行数和字节上限；
- AI 调用设置令牌、超时、重试和费用上限；
- 文档提取设置文件大小、页数和 OCR 时间上限；
- 情景计算优先在浏览器或本地 worker 完成；
- 批量任务使用独立工作目录，不覆盖已冻结版本。

### 10.5 重试策略

只对临时错误重试：

- 网络超时；
- AI 服务限流；
- 数据库短暂不可用；
- 文件读取锁定。

不对以下情况自动重试并覆盖结果：

- 字段语义冲突；
- 证据缺少原文或定位；
- 截止时间违规；
- 单位和币种冲突；
- 因果门禁失败。

## 11. 审计和时间策略

每个运行必须记录：

```text
领域包版本
公司适配器版本
数据快照版本
数据截止时间
证据版本
参数版本
输入情景
运行时间
运行 ID
输入哈希和结果哈希
```

证据需要双时钟：

- `published_at`：资料首次公开时间；
- `anchor_at`：研究截止或事件锚点时间。

资料角色：

```text
AS_OF_EVIDENCE
POST_EVENT_VALIDATION
CUTOFF_BLOCKED
```

来源事实必须由 T1/T2 原文支持，且具备：

```text
evidence_id
source_url
publisher
published_at
original_quote
locator
snapshot_sha256
supports_node_ids
acceptance_status
```

因果状态与证据状态独立保存：

```json
{
  "status": "NOT_IDENTIFIED",
  "causal_attribution_allowed": false,
  "causal_conclusion": "ABSTAIN",
  "unmet_conditions": [],
  "confounders": [],
  "counterevidence": []
}
```

## 12. UI 设计

### 12.1 固定六层横向结构

六个标题、节点和连线使用同一套几何配置：

```text
宏观 / 外部变量
行业需求与价格
供给与生产路线
库存 / 产能约束
产业价值池
关键公司
```

缩放时只改变共享画布变换，标题位置从同一列中心计算，禁止标题单独使用另一套坐标。

### 12.2 数据状态可视化

必须区分：

- 数据库候选值；
- 公司披露事实；
- 管理层指引；
- 市场预期；
- 分析假设；
- 计算结果；
- 待人工审核；
- 数据缺失；
- 隔离数据。

页面必须保留 `NEEDS_HUMAN_REVIEW`、`formal_ready=false` 和 `ABSTAIN`，不能用综合可信度分数掩盖关键缺口。

### 12.3 公司视图

点击公司后固定显示：

```text
公司基本信息
→ 产业暴露
→ 公司专属经营模型
→ 收入变化
→ 利润率变化
→ CapEx
→ FCF
→ 估值贡献
→ 证据与失效条件
```

### 12.4 多行业切换

```text
领域包选择
公司 / 行业筛选
匹配状态筛选
输出等级筛选
数据截止时间
运行版本
```

不匹配节点不显示为正常结果，可显示为灰色、折叠或 `UNAVAILABLE`。

## 13. 版本与部署

### 13.1 静态部署

适合已冻结领域包：

```text
静态 HTML / CSS / JS
    + domain-package.zip
    + 浏览器本地确定性计算
```

不需要 API Key、数据库服务器或在线 AI。

### 13.2 本地工作台

适合用户接入自己的数据库：

```text
静态页面
    ↔ localhost 本地连接器
             ├── MySQL / PostgreSQL 只读连接
             ├── AI API 配置
             ├── 数据扫描
             ├── 映射审核
             └── 数据包导出
```

密码和原始数据保留在本机，适合金融数据和内网环境。

### 13.3 在线服务

适合多人协作：

```text
静态前端 + API + 任务队列 + 数据库 + 可选 AI 网关
```

API Key 支持平台密钥、用户自带密钥和企业内部模型三种方式。任何密钥都不得进入前端打包文件。

## 15. 门禁和失败处理

以下情况必须停止晋级并隔离：

- 关键来源无原文或稳定定位；
- 资料发布时间晚于研究截止时间；
- 公司、行业或指标映射有歧义；
- 币种、单位、期间或报表口径冲突；
- 关键节点缺失却要求精确估值；
- 传播参数没有任何校准依据；
- 同一证据 ID 的关键字段冲突；
- 行情窗口无法连续交易核验；
- 因果门禁未通过却试图输出因果结论。

隔离记录必须保留：

```text
对象 ID
失败原因码
原始输入
相关证据
映射版本
发现时间
建议人工动作
```

## 17. 验收标准

- 静态数据包可以在无 AI、无数据库服务器的情况下运行；
- 任意结果可以追溯到输入、公式、参数、时间和证据；
- 五家公司使用不同经营模型；
- 缺失节点不被零值或猜测填补；
- `MATCHED`、`PARTIAL`、`UNAVAILABLE`、`CONFLICTED` 状态可视化；
- 相同版本和相同输入得到完全一致的结果；
- 六个横向标题在桌面和窄屏缩放后仍与节点对齐；
- AI 输出未确认前不能进入正式候选包；
- 数据库凭据不进入前端、日志和数据包；
- 任务重复提交不会重复写入或重复调用 AI；
- 失败任务可以隔离，不阻塞其他行业包；
- 因果状态非 `IDENTIFIED` 时始终显示 `ABSTAIN`；
- V2.8 基线和独立实验版本保持不可变。

## 18. 当前建议

第一版不要直接追求“上传任意数据库后自动生成完整沙盘”。建议先完成以下可交付闭环：

```text
用户连接 workspace MySQL / PostgreSQL
→ 扫描字段
→ 规则完成大部分识别
→ AI 推荐不确定映射
→ 用户确认
→ 生成 coal-steel 数据包
→ 静态焦煤沙盘加载
→ 浏览器本地复算
```

这条闭环稳定后，再把同一个连接器接入 AI 基础设施和新能源汽车领域包。多行业能力的判断标准不是“节点数量更多”，而是“领域包可替换、公司模型不混用、缺失数据能降级、结果可复算”。
