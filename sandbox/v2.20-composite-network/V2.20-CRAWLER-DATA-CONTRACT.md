# V2.20 爬虫到网络数据库正式契约

契约版本：`nexus-crawler-batch-1.0.0`

本契约规定所有行业采集器的统一输出。新增行业时，采集器只负责把来源内容转换成该契约；数据库和网络浏览器不再为行业名称增加专用字段。

## 一、三层数据结构

```text
RAW 原始层
  ingestion_runs
  source_registry
  raw_documents
  evidence

STANDARD 标准事实层
  entities
  metric_definitions
  metric_values
  quarantine

NETWORK 网络层
  network_registry
  network_layers
  formulas
  network_nodes
  network_edges
  network_versions
```

### 写入原则

- 爬虫必须先写 `raw_documents`，不能只写最终数值。
- 每个 `metric_values` 必须指向一条 `evidence`。
- 每条 `evidence` 必须指向一个原始文档或可复现 API 响应。
- 普通数值采集器不得自行编造网络关系。
- 只有来源明确披露的关系、规则模板关系或 AI 审核通过的候选关系才能进入 `network_edges`。
- `AI_APPROVED` 关系自动作为候选传播，但 `parameter_status` 必须保持 `AI_ASSUMPTION`，因果结论保持 `ABSTAIN`。

## 二、采集批次格式

每次爬取形成一个批次：

```json
{
  "contract_version": "nexus-crawler-batch-1.0.0",
  "network": {},
  "batch": {},
  "sources": [],
  "documents": [],
  "evidence": [],
  "layers": [],
  "entities": [],
  "metric_definitions": [],
  "observations": [],
  "formulas": [],
  "relations": []
}
```

`documents/evidence/observations` 是普通数据采集必需内容；`layers/formulas/relations` 只有在来源或领域模板能够支持时才提供。

## 三、网络身份 `network`

必填：

```text
network_id            稳定且全局唯一的网络 ID
domain_code           行业或领域代码，必须与 batch.domain_code 一致
network_name          网页总标题，不允许由前端猜测
network_version       本次网络版本
network_kind          网络类型，例如 INDUSTRY_COMPOSITE
network_status        DRAFT / CANDIDATE / ACTIVE / FROZEN / DISABLED
data_cutoff           YYYY-MM-DD，必须与 batch.data_cutoff 一致
causal_status         ABSTAIN / CONDITIONAL / IDENTIFIED
```

同一行业可以有多个网络版本；`network_id` 用于稳定归属，`network_version` 用于保留历史。网页总标题必须直接读取 `network_name`。

## 四、批次 `batch`

必填：

```text
batch_id             全局唯一批次 ID
domain_code          行业或领域代码
collector_code       采集器代码
collector_version    采集器版本
started_at           ISO-8601 UTC 时间
completed_at         ISO-8601 UTC 时间
data_cutoff          YYYY-MM-DD
run_type             DAILY / BACKFILL / MANUAL / REPAIR
status               SUCCEEDED / PARTIAL / FAILED
```

推荐 ID：

```text
batch::{domain_code}::{collector_code}::{YYYYMMDDTHHMMSSZ}
```

同一个 `batch_id` 重复提交必须幂等，不得重复生成指标值。

## 五、来源 `sources`

必填：

```text
source_code
source_name
source_type          WEB / API / CSV / PDF / DATABASE
publisher
base_url
source_tier          T1 / T2 / T3 / MARKET_PROXY
license_status       ALLOWED / RESTRICTED / UNKNOWN
status               ACTIVE / PAUSED / DISABLED
```

`T1`通常为监管机构、交易所、政府和公司正式公告；`T2`为可靠行业机构；`T3`为二次转载；`MARKET_PROXY`为行情或代理指标。

## 十、指标观测 `observations`

必填：

```text
observation_id
metric_code
value
unit
as_of_date
available_at
data_cutoff
evidence_id
quality_status
source_row_key
revision
```

按指标范围填写：

```text
entity_code          公司或实体指标必填
currency             金额和价格指标按需要填写
report_period        财务指标必填
dimensions           地区、产品、口径等附加维度
```

日期含义：

```text
as_of_date       指标代表的业务日期
report_period    财务报告期
published_at     来源发布时间
available_at     当时真正可以获得该数据的时间
data_cutoff      本次网络允许使用的数据截止日
```

必须满足：

```text
available_at <= data_cutoff 当日结束时间
```

否则进入隔离区，防止未来数据泄漏。

`quality_status`：

```text
SOURCE_FACT
REPORTED_ACTUAL
MARKET_PROXY
AI_EXTRACTED
CALCULATED_LINEAGE
PENDING_REVIEW
REJECTED
```

推荐去重键：

```text
domain_code
metric_code
entity_code
as_of_date
report_period
dimensions
revision
evidence_id
```

## 十三、关系 `relations`

必填：

```text
relation_id
source_metric_code
target_metric_code
direction
relation_type
formula_id
status
parameter_status
mechanism
```

建议字段：

```text
entity_scope
weight
candidate_weight
lag_days
confidence
impact_cap_pct
evidence_ids
invalidation
```

`status`：

```text
CONFIRMED
AI_APPROVED
CANDIDATE
NEEDS_HUMAN_REVIEW
DISABLED
```

写入规则：

- `CONFIRMED`使用 `weight`，需要正式证据和已确认参数。
- `AI_APPROVED`使用 `candidate_weight`，网页显示候选虚线，保持 `ABSTAIN`。
- `weight / candidate_weight`始终填写正数幅度；正向或负向只能由 `direction` 表示，禁止在权重中重复写负号。
- 没有公式、端点或机制说明的关系进入隔离区。

## 十四、稳定 ID 规则

所有 ID 使用规范化字段生成 SHA-256，避免重复爬取产生新记录：

```text
document_id    = hash(source_code, canonical_url, published_at, content_sha256)
evidence_id    = hash(document_id, locator, original_quote)
observation_id = hash(metric_code, entity_code, as_of_date, report_period,
                      dimensions, revision, evidence_id)
relation_id    = hash(domain_code, source_metric_code, target_metric_code,
                      entity_scope, formula_id)
```

## 十五、隔离而非整批失败

以下问题只隔离单条对象：

```text
字段无法识别
指标单位需要换算
未知公式
证据缺少定位
未来日期
关系缺少参数
重复但内容冲突
```

以下问题阻止整个批次进入网络：

```text
contract_version 不支持
batch_id 缺失
文档哈希非法
主键重复且内容冲突
指标引用不存在
关系端点不存在
网络层级结构非法
```

## 十六、网络生成最低条件

```text
DATA_READY:
  至少一个有效实体或行业指标
  至少一个通过证据校验的 observation

GRAPH_READY:
  节点存在且层级有效
  关系端点全部存在
  阻断性结构错误为 0

SCENARIO_READY:
  至少一个可调节点
  至少一条受支持公式的传播关系
  至少一条可调节点到结果节点的完整路径
```

## 十七、采集器实现要求

每个新采集器只需要实现：

```text
fetch()       下载并保存原始响应
snapshot()    计算哈希并登记 raw_documents
extract()     生成 evidence 和 observations
validate()    按本契约校验
commit()      幂等写入数据库
report()      输出批次统计和隔离原因
```

采集器不得直接修改网页文件，也不得绕过标准事实层直接生成不可追溯的网络节点。

## 十八、固定入库与网络编译映射

每个 JSON 区块只写入固定位置：

```text
network             -> network_registry
batch               -> ingestion_runs
sources             -> source_registry
documents           -> raw_documents
evidence            -> evidence
layers              -> network_layers
entities            -> entities
metric_definitions  -> metric_definitions
observations        -> metric_values
formulas            -> formulas
relations           -> network_edges
```

`network_nodes` 不要求爬虫逐条编造，而由网络编译器按以下确定性规则生成：

1. 只读取 `ACTIVE` 指标定义以及已经通过证据、时间和单位校验的最新观测。
2. 节点 ID 由 `network_id + metric_code + entity_code` 稳定生成。
3. 节点标题由 `entity_name + metric_name` 生成；没有实体范围时只用 `metric_name`。
4. 节点分类读取 `default_layer_code`，总标题读取 `network.network_name`。
5. 关系按 `source_metric_code / target_metric_code` 展开到节点；端点不存在时整批停止编译。
6. `AI_APPROVED` 自动转换为候选可传播关系，使用 `candidate_weight`，同时保持 `AI_ASSUMPTION / ABSTAIN`。
7. 未知公式、单位不一致或未来数据只隔离相关对象，不删除已经验证的其他路径。
8. 只有可调节点到结果层节点存在完整路径时，网络才标记为 `SCENARIO_READY`。
